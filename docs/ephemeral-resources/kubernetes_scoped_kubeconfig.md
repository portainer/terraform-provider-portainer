# portainer_kubernetes_scoped_kubeconfig (Ephemeral Resource)

The `portainer_kubernetes_scoped_kubeconfig` ephemeral resource issues a read-only kubeconfig limited to some namespaces of one Kubernetes environment for the duration of one Terraform run. It is issued (`POST /kubernetes/{id}/scoped_kubeconfig`) when Terraform opens the ephemeral resource and revoked (`DELETE /kubernetes/{id}/scoped_kubeconfig/{kcId}`) when it closes it, which also removes the service account and role bindings Portainer created. The kubeconfig is never written to the plan or the state.

When the kubeconfig has to outlive the run, use the [`portainer_kubernetes_scoped_kubeconfig` resource](../resources/kubernetes_scoped_kubeconfig.md).

> **Requirements:** Terraform >= 1.10 or OpenTofu >= 1.11 (ephemeral resources), Portainer Business Edition 2.45.2 or later. On Community Edition or an older server the error says so.

## Example Usage

```hcl
ephemeral "portainer_kubernetes_scoped_kubeconfig" "reader" {
  environment_id = 4
  expiry_seconds = 3600
  namespaces     = ["default", "monitoring"]
  description    = "terraform run"
}

provider "kubernetes" {
  # Read the kubeconfig from the ephemeral value, e.g. via yamldecode().
  host  = yamldecode(ephemeral.portainer_kubernetes_scoped_kubeconfig.reader.kubeconfig).clusters[0].cluster.server
  token = yamldecode(ephemeral.portainer_kubernetes_scoped_kubeconfig.reader.kubeconfig).users[0].user.token
}
```

## Lifecycle & Behavior

- Every `plan` and every `apply` issues its own kubeconfig and revokes it when the run ends.
- `expiry_seconds` bounds its life should the revocation not happen (e.g. Terraform is killed). Portainer cannot extend a kubeconfig, so there is no renewal: choose an expiry longer than the run.
- When Portainer revokes the credential but cannot remove its Kubernetes objects (status 500), the run gets a warning, not an error, as with the resource.

## Schema

### Required

- `environment_id` (Number) Identifier of the Portainer Kubernetes environment the kubeconfig gives access to.
- `expiry_seconds` (Number) Lifetime of the kubeconfig in seconds, at most 604800 (7 days). It is revoked at the end of the run anyway; the expiry bounds its life should the revocation fail.

### Optional

- `description` (String) Free-text description shown in Portainer's list of scoped kubeconfigs while the kubeconfig exists.
- `include_secrets` (Boolean) Whether the kubeconfig can read Secrets. Defaults to false. Granted only where the caller can view secrets, and never in the `portainer` and `portainer-addon-*` namespaces.
- `namespaces` (List of String) Namespaces the kubeconfig can read, within the caller's own access. Leave unset for every namespace the caller can view; the `portainer` and `portainer-addon-*` namespaces are covered only when named.

### Read-Only

- `covered_namespaces` (List of String) Namespaces the kubeconfig actually covers, as reported by Portainer.
- `expires_at` (Number) Time the kubeconfig stops working, as a Unix timestamp.
- `kubeconfig` (String, Sensitive) The kubeconfig document.
- `scoped_kubeconfig_id` (Number) Portainer identifier of the scoped kubeconfig.
- `service_account` (String) Kubernetes service account the kubeconfig authenticates as.
