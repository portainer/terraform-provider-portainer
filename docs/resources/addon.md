# portainer_addon (Resource)

> **Business Edition only.** This endpoint does not exist in Portainer CE.

Installs, upgrades and uninstalls an addon from the Portainer add-on store. Portainer installs an addon as a Helm release, so the resource is essentially a managed release pinned to a catalog entry.

## Example Usage

```hcl
resource "portainer_addon" "portal" {
  addon_id = "portal-template"
  version  = "1.2.3"

  values = jsonencode({
    ingress = {
      enabled = true
      host    = "apps.example.com"
    }
    replicas = 2
  })
}
```

Installing from a private registry instead of the catalog's public chart reference:

```hcl
resource "portainer_addon" "portal" {
  addon_id          = "portal-template"
  registry_id       = portainer_registry.internal.id
  chart             = "portainer/charts/portal"
  image_registry_id = portainer_registry.internal.id
}
```

## Schema

### Required

- `addon_id` (String) Catalog identifier of the addon, for example `portal-template`. Use the `portainer_addons` data source to list what the connected Portainer offers.

### Optional

- `chart` (String) Chart path within `registry_id`, for example `portainer/charts/portainer-run`. Required when `registry_id` is set; leave unset to install from the catalog's public chart reference.
- `force_uninstall` (Boolean) Whether to force the uninstall when the addon is destroyed, which lets Portainer remove a release that is in a broken state.
- `image_registry_id` (Number) Identifier of the Portainer registry whose credentials the addon's pods pull their container image with. Unlike `registry_id` this can be changed on an upgrade. Leave unset to keep whatever the addon is installed with.
- `prune_config_on_uninstall` (Boolean) Whether to also delete the addon's stored configuration entries when the addon is destroyed. By default the configuration survives an uninstall so a reinstall keeps it.
- `public_url` (String) URL users open the addon at, for example `https://run.example.com`. Portainer signs users in to the addon only by sending them back to this URL. Requires Portainer Business Edition 3.1 or later; leave unset to keep whatever is set in Portainer. Removing it from the configuration clears the URL.
- `registry_id` (Number) Identifier of the Portainer registry the chart is pulled from. Only honoured on a first install, so changing it reinstalls the addon. Leave unset to use the catalog's public chart reference.
- `values` (String) Helm value overrides as a JSON object, merged over Portainer's per-addon defaults. Use `jsonencode({...})` to build it.
- `version` (String) Chart version to install. Leave unset to resolve the latest published version at apply time - note that Portainer then picks the version, so the installed one is reported in `chart_version` rather than here.

### Read-Only

- `available_versions` (List of String) Published stable chart versions, newest first. Empty when the lookup could not run, in which case `version_check_error` says why.
- `chart_path` (String) Chart path recorded for the installed release, empty when the chart came from the public reference.
- `chart_version` (String) Chart version actually installed, which is what to read when `version` is left unset.
- `description` (String) Full catalog description of the addon.
- `display_name` (String) Human-readable name of the addon as published in the catalog.
- `enabled` (Boolean) Whether the addon is installed and switched on. Manage it with `portainer_addon_access`.
- `health_message` (String) Explanation of an unhealthy probe result, empty otherwise.
- `health_status` (String) Live probe of the running addon: `healthy`, `unhealthy`, `credential-invalid` or `unknown`. Orthogonal to `lifecycle_status` - an installed addon can be unhealthy.
- `helm_chart_repository` (String) Public OCI chart reference the catalog publishes for the addon.
- `icon` (String) Icon the Portainer UI shows for the addon.
- `id` (String) Identifier of the resource.
- `lifecycle_status` (String) Helm release lifecycle state: `installing`, `upgrading`, `installed`, `failed`, `unknown` or `uninstalling`. This is not a health status.
- `lifecycle_status_message` (String) Explanation of a failed install or upgrade, empty after a clean one.
- `path` (String) Path the addon is served under in Portainer.
- `short_description` (String) One-line catalog tagline for the addon.
- `upgrade_available` (Boolean) Whether a newer chart version than the installed one has been published.
- `version_check_error` (String) Why the available-version lookup failed, empty when it succeeded.

## Notes on Arguments and Attributes

- `addon_id`: Changing it forces a new resource.
- `force_uninstall`: Defaults to `false`.
- `prune_config_on_uninstall`: Defaults to `false`, so the configuration survives a reinstall.
- `public_url`: Portainer BE 3.1+, with Portainer itself running on Kubernetes (add-ons are not available otherwise). Set through its own endpoint, so changing only the URL does not reinstall the addon. Only sent when configured (an older Portainer is never asked), read back while configured, and cleared in Portainer when removed from the configuration. Portainer signs users in to the addon only by redirecting them to this URL.

## Attributes Reference

`lifecycle_status` and `health_status` are independent: an addon can report `installed` while its probe says `unhealthy`, and it can be `upgrading` while the previous version still serves traffic. A `credential-invalid` health status is what `portainer_addon_repair` fixes.

## Import

```bash
terraform import portainer_addon.portal portal-template
```

The import ID is the addon's catalog identifier.
