# portainer_addon_repair (Resource)

> **Business Edition only.** This endpoint does not exist in Portainer CE.

Reissues the credential an installed addon authenticates to Portainer with. Run it when an addon reports `health_status = "credential-invalid"`.

> **See also:** the [`portainer_addon_repair` action](../actions/addon_repair.md) (Terraform >= 1.14) runs the same operation on demand or from a lifecycle `action_trigger`, without a resource in state.

## Example Usage

```hcl
resource "portainer_addon_repair" "portal" {
  addon_id = portainer_addon.portal.addon_id

  triggers = {
    health = portainer_addon.portal.health_status
  }
}
```

## Schema

### Required

- `addon_id` (String) Catalog identifier of the addon whose credential is repaired, for example `portal-template`. Repair the addon when its `health_status` reports `credential-invalid`.

### Optional

- `triggers` (Map of String) Arbitrary values that force another repair when they change. A repair is a one-shot action, so without a trigger the resource runs once and then stays put.

### Read-Only

- `chart_version` (String) Chart version of the addon, as reported after the repair.
- `enabled` (Boolean) Whether the addon is enabled, as reported after the repair.
- `id` (String) Identifier of the resource.
- `lifecycle_status` (String) Helm release lifecycle state of the addon, as reported after the repair.
- `lifecycle_status_message` (String) Explanation of a failed lifecycle operation, as reported after the repair.

## Notes on Arguments and Attributes

- `addon_id`: Changing it forces a new resource.
