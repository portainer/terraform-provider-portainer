# portainer_kubernetes_deployment_scale (Resource)

The `portainer_kubernetes_deployment_scale` resource manages the replica count of a Kubernetes deployment that already exists in the cluster, using Portainer's native scale API.

It manages **only** the replica count: the deployment itself must be created elsewhere (for example with `portainer_kubernetes_application`, a stack, or Helm). The replica count is read back on refresh, so scaling done outside Terraform shows up as drift.

Deleting the resource stops managing the replica count and leaves the deployment running at its current scale — scaling has no inverse. Set `replicas = 0` to stop the workload.

Requires Portainer **2.45.0** or newer.

> **See also:** the [`portainer_kubernetes_deployment_scale` action](../actions/kubernetes_deployment_scale.md) (Terraform >= 1.14) runs the same operation on demand or from a lifecycle `action_trigger`, without a resource in state.

## Example Usage

```hcl
resource "portainer_kubernetes_deployment_scale" "web" {
  environment_id  = 1
  namespace       = "default"
  deployment_name = "web"
  replicas        = 3
}

output "web_ready_replicas" {
  value = portainer_kubernetes_deployment_scale.web.ready_replicas
}
```

## Schema

### Required

- `deployment_name` (String) Name of the deployment to scale. The deployment must already exist; this resource manages only its replica count.
- `environment_id` (Number) Identifier of the Portainer Kubernetes environment the deployment belongs to.
- `namespace` (String) Namespace the deployment lives in.
- `replicas` (Number) Desired number of replicas. Changing this scales the deployment in place.

### Read-Only

- `available_replicas` (Number) Number of replicas available for at least the configured minimum ready seconds, as reported after the scale request.
- `id` (String) Identifier of the scale, `<environment_id>/<namespace>/<deployment_name>/scale`.
- `ready_replicas` (Number) Number of replicas passing their readiness checks, as reported after the scale request.

## Notes on Arguments and Attributes

- `environment_id`: Changing this replaces the resource.
- `namespace`: Changing this replaces the resource.
- `deployment_name`: Changing this replaces the resource.

## Attributes Reference

Both attributes are a snapshot taken at the moment of the request: the cluster needs time to converge, so a freshly scaled deployment normally reports fewer ready replicas than requested until the next refresh.
