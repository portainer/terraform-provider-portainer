# portainer_backup_s3 (Resource)

The `portainer_backup_s3` resource allows you to back up your Portainer instance to an AWS S3 bucket or compatible storage system.
> ⚠️ Note: This resource performs a one-time backup upload on every terraform apply. It is not stateful and will always re-trigger.

> Currently working only for Portainer BE edition

> **See also:** the [`portainer_backup_s3` action](../actions/backup_s3.md) (Terraform >= 1.14) runs the same operation on demand or from a lifecycle `action_trigger`, without a resource in state.

## Example Usage

```hcl
resource "portainer_backup_s3" "s3_backup" {
  access_key_id      = "s3_access_key"
  secret_access_key  = "s3_secret_key"
  bucket_name        = "s3_bucket"
  region             = "s3_region"
  s3_compatible_host = "s3_endpoint"
  password           = "backup_password"
  cron_rule          = var.backup_cron_rule   # optional
}
```
- [Example on GitHub](https://github.com/portainer/terraform-provider-portainer/tree/main/examples/backup_s3)

## Lifecycle & Behavior
This resource does not track state — it performs a one-time backup to the specified S3 bucket every time terraform apply runs.

## Schema

### Required

- `access_key_id` (String, Sensitive) Sensitive S3 access key identifier used to upload the Portainer backup archive.
- `bucket_name` (String) Name of the S3 bucket where the Portainer backup archive will be stored.
- `region` (String) AWS or S3-compatible region of the destination bucket.
- `s3_compatible_host` (String) Endpoint URL of the S3 or S3-compatible service used for the backup upload.

### Optional

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `cron_rule` (String) Optional cron expression that schedules recurring S3 backups in Portainer.
- `password` (String, Sensitive) Sensitive password used to encrypt the Portainer backup archive before upload. Stored in state as a sensitive value; use `password_wo` to keep it out of state.
- `password_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) Write-only password used to encrypt the backup archive (supports ephemeral values; never stored in Terraform state). Conflicts with `password`. Requires Terraform 1.11 or later.
- `password_wo_version` (Number) Version of `password_wo`. Increment it to send a new value. Changing it forces resource recreation.
- `secret_access_key` (String, Sensitive) Sensitive S3 secret access key paired with `access_key_id`. Stored in state as a sensitive value; use `secret_access_key_wo` to keep it out of state.
- `secret_access_key_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) Write-only S3 secret access key (supports ephemeral values; never stored in Terraform state). Conflicts with `secret_access_key`. Requires Terraform 1.11 or later.
- `secret_access_key_wo_version` (Number) Version of `secret_access_key_wo`. Increment it to send a new value. Changing it forces resource recreation.

### Read-Only

- `id` (String) Identifier of the resource.
- `last_run_failed` (Boolean) Whether the most recent scheduled S3 backup failed.
- `last_run_timestamp` (String) UTC timestamp of the most recent scheduled S3 backup, empty when none has run.

## Notes on Arguments and Attributes

- `region`: AWS region (e.g., `eu-central-1`)
- `s3_compatible_host`: Hostname of S3-compatible provider (e.g., `https://s3.example.com`)
- `cron_rule`: Optional cron rule for scheduling backups (e.g., `@daily`) *(not yet stored in state)*.
- `password` / `password_wo`: One of them is required. A Portainer Business Edition 3.1 instance in FIPS mode refuses unencrypted backups and stops running a schedule without a password, so do not set it to an empty string there.

## Scheduled run status

Both are read from Portainer's S3 backup status endpoint and are informational: an instance that has never run a scheduled backup simply reports nothing, and the read does not fail over it.
