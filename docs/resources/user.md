# portainer_user (Resource)

The `portainer_user` resource allows you to manage user accounts in Portainer.

## Example Usage

### Internal User

```hcl
resource "portainer_user" "your-user" {
  username = "youruser"
  password = "strong-password"
  role     = 1 # 1 = admin, 2 = standard user
}
```

### Internal User with make api key
```hcl
resource "portainer_user" "your_user" {
  username = "youruser"
  password = "strong-password"
  role     = 1 # 1 = admin, 2 = standard user

  generate_api_key     = true
  api_key_description  = "GitHub Actions token"

  # Exposed output (optional)
  lifecycle {
    ignore_changes = [api_key_raw]
  }
}

output "your_user_api_key" {
  value     = portainer_user.your_user.api_key_raw
  sensitive = true
}

```

### LDAP User
```hcl
resource "portainer_user" "your-user" {
  username  = "youruser"
  role      = 2
  ldap_user = true
}
```

### Import

- You can import an existing user by its numeric ID or by its username.

#### Import by ID

```bash
terraform import portainer_user.your_user 123
```

#### Import by Username

```bash
terraform import portainer_user.your_user youruser
```

#### Import by identity

Terraform 1.12 and later can also import by resource identity: the object's numeric ID as `id` in an `import` block. The ID string above keeps working.

```hcl
import {
  to       = portainer_user.example
  identity = {
    id = "5"
  }
}
```

`terraform query` (Terraform 1.14+) with the [`portainer_user` list resource](../list-resources/user.md) finds the objects to import and can generate the `import` blocks (`terraform query -generate-config-out=generated.tf`). The identity is stored in the state from v3.1.0 on; state written by v3.0.0 gets it on the next refresh, without a plan change. OpenTofu supports neither resource identity nor list resources; it keeps importing by ID.

## Lifecycle & Behavior

Users are updated if any of the attributes change (e.g., username, password, role).

- To delete a user created via Terraform, simply run:
```hcl
terraform destroy
```

- To change a user's role, update the role field and re-apply:
```hcl
terraform apply
```

## Schema

### Required

- `username` (String) Username used to log in to Portainer. Must be unique within the Portainer instance.

### Optional

- `api_key_description` (String) Description applied to the generated Portainer API key. Only used when generate_api_key is true.
- `generate_api_key` (Boolean) Whether to generate a Portainer API key for the user during creation. Requires password to be set.
- `ldap_user` (Boolean) Whether the user is authenticated via LDAP. When true, password must be empty and authentication is delegated to the configured LDAP server.
- `password` (String, Sensitive) Password for the Portainer user. Required for non-LDAP users; must be omitted for LDAP users. Stored in state as a sensitive value.
- `role` (Number) Portainer role of the user: 1 = administrator, 2 = standard user. Defaults to 2.
- `team_id` (Number) Optional Portainer team ID the user is a member of. Only applicable for standard users (role = 2). Memberships managed with `portainer_team_membership` are not reflected here.

### Read-Only

- `api_key_raw` (String, Sensitive) Raw API key generated by Portainer when generate_api_key is true. Computed and only available after initial creation.
- `created_authentication_method` (String) Authentication method used when the user was created (Portainer 3.0+). One of `internal`, `ldap` or `oauth` (Portainer `portainer.AuthenticationMethod` 1/2/3). Empty on Portainer releases before 3.0, which do not report it, and when the server has not recorded it.
- `id` (String) Identifier of the resource.
- `last_authentication_method` (String) Authentication method used at the user's last login (Portainer 3.0+). One of `internal`, `ldap` or `oauth` (Portainer `portainer.AuthenticationMethod` 1/2/3). Empty on Portainer releases before 3.0, which do not report it, and when the server has not recorded it.

## Notes on Arguments and Attributes

- `password`: Not allowed when `ldap_user = true`.
- `ldap_user`: Defaults to `false`.
- `team_id`: Can only be used when `role = 2` (standard user).
- `generate_api_key`: Defaults to `false`.
- `api_key_description`: Defaults to `"terraform-generated-api-key"`.
- `id`: ID of the Portainer user.

> ⚠️ If `ldap_user = true`, the `password` must be omitted.  
> ⚠️ `team_id` is ignored for admin users (`role = 1`).  
> ℹ️ `team_id` tracks only the membership it creates: memberships managed with `portainer_team_membership` do not show up in it. Changing `team_id` moves the user to the new team.
