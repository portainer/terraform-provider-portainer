# portainer_restore (Resource)

The `portainer_restore` resource restores a Portainer instance from a backup archive, the counterpart of `portainer_backup`.

A restore replaces the instance's entire database. Portainer only accepts it on an instance that has **not been initialised yet**, which is why `setup_token_wo` exists — so this belongs in a bootstrap configuration, not alongside resources that manage a running instance.

## Example Usage

```hcl
resource "portainer_restore" "bootstrap" {
  file_content_base64    = filebase64("portainer-backup.tar.gz")
  file_name              = "portainer-backup.tar.gz"
  password               = var.backup_password
  setup_token_wo         = var.setup_token
  setup_token_wo_version = 1
}
```

- `file_content_base64_wo_version` (Number) Version of `file_content_base64_wo`. Increment it to send a new value. Changing it forces resource recreation.
- `file_name` (String) Name reported to Portainer for the uploaded archive.
- `password` (String, Sensitive) Password the backup was encrypted with. Leave unset for an unencrypted backup. Stored in state as a sensitive value; use `password_wo` to keep it out of state.
- `password_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) Write-only password the backup archive was encrypted with (supports ephemeral values; never stored in Terraform state). ## Notes on Arguments and Attributes

- `id`: Synthetic identifier carrying a timestamp.

Every argument forces a new resource: a restore is a one-shot operation with nothing to update.

## Attributes Reference

**A backup archive contains every credential Portainer holds.** Both the archive and its password end up in Terraform state — treat that state as a secret, or drive the restore from a configuration whose state is stored securely and separately.
