# portainer_docker_node (Resource)

The `portainer_docker_node` resource allows you to update, inspect, and delete Docker Swarm nodes via the Portainer API.

You can change attributes such as availability, role, name or labels, or even remove the node entirely from the cluster using this resource.

## Example Usage
```hcl
resource "portainer_docker_node" "example" {
  endpoint_id  = 1
  node_id      = "wna048ajhbc1n1t5ispvf6mvg"
  version      = 4869
  name         = "node-name"
  availability = "active"
  role         = "manager"

  labels = {
    foo = "barrerun"
  }
}

```

## Lifecycle & Behavior
- You can update node's role, availability, name, or labels by running:
```hcl
terraform apply
```

- To destroy the node:
```hcl
terraform destroy
```

## Schema

### Required

- `endpoint_id` (Number) ID of the Portainer environment (Docker Swarm cluster) where the node is managed.
- `node_id` (String) Docker Swarm node ID to update.
- `version` (Number) Swarm node version required for update operation

### Optional

- `availability` (String) Desired availability of the Swarm node (active, pause, or drain).
- `labels` (Map of String) Key/value labels assigned to the Swarm node for placement and selection.
- `name` (String) Desired display name for the Swarm node.
- `role` (String) Desired role of the Swarm node (worker or manager).

### Read-Only

- `id` (String) Identifier of the resource.

## Notes on Arguments and Attributes

- `id`: A combination of endpoint ID and node ID (`{endpoint}-{node}`)

## Import

Swarm nodes can be imported as `<endpoint_id>:<node_id>`. The format from before v3.0.0, `<endpoint_id>-<node_id>`, is still accepted.

```shell
terraform import portainer_docker_node.example 1:ktnbjxoalbkvbvedmg1urrz8h
```

### Import by identity

Terraform 1.12 and later can also import by resource identity: the environment ID as `endpoint_id` and the Swarm node ID as `node_id` in an `import` block. The ID string above keeps working.

```hcl
import {
  to       = portainer_docker_node.example
  identity = {
    endpoint_id = 1
    node_id     = "ktnbjxoalbkvbvedmg1urrz8h"
  }
}
```

`terraform query` (Terraform 1.14+) with the [`portainer_docker_node` list resource](../list-resources/docker_node.md) finds the objects to import and can generate the `import` blocks (`terraform query -generate-config-out=generated.tf`). The identity is stored in the state from v3.1.0 on; state written by v3.0.0 gets it on the next refresh, without a plan change. OpenTofu supports neither resource identity nor list resources; it keeps importing by ID.
