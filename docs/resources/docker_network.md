# portainer_docker_network (Resource)

The `portainer_docker_network` resource allows you to manage Docker networks on a specific environment (endpoint) in Portainer.
You can define bridge or overlay networks, including driver-specific options, labels, and IPAM settings.

## Example Usage

### Create a basic bridge network
```hcl
resource "portainer_docker_network" "bridge_network" {
  endpoint_id = 1
  name        = "new-bridge-network"
}
```

### Create an attachable bridge network with options and labels
```hcl
resource "portainer_docker_network" "bridge_network_with_configuration" {
  endpoint_id = 1
  name        = "new-bridge-network-with-configuration"
  attachable  = true

  options = {
    "com.docker.network.bridge.enable_icc"           = "true"
    "com.docker.network.bridge.enable_ip_masquerade" = "true"
  }

  labels = {
    "env"     = "test"
    "project" = "terraform"
  }
}
```

### Create a network with custom IPAM config
```hcl
resource "portainer_docker_network" "network_with_ipam" {
  endpoint_id = 1
  name        = "new-ipam-network"
  driver      = "bridge"
  attachable  = true
  ipam_driver = "default"

  ipam_config {
    subnet    = "192.168.100.0/24"
    gateway   = "192.168.100.1"
    ip_range  = "192.168.100.0/25"
  }

  ipam_options = {
    foo = "bar"
  }
}
```

## Lifecycle & Behavior
- To delete a docker netowrk created via Terraform, simply run:
```hcl
terraform destroy
```
Docker networks are immutable in Portainer. To update, you must destroy and recreate them.
- To modify a name (e.g., make it dynamic), update the attributes and re-apply:
```hcl
terraform apply
```

## Schema

### Required

- `endpoint_id` (Number) ID of the Portainer environment (Docker host or Swarm) where the network is created.
- `name` (String) Name of the Docker network.

### Optional

- `attachable` (Boolean) Whether standalone containers may attach to this Swarm overlay network.
- `config_from` (String) Name of a config-only network from which to copy configuration.
- `config_only` (Boolean) Whether this is a config-only network that contains only configuration for other networks.
- `driver` (String) Driver used by the Docker network (e.g., bridge, overlay, macvlan, host, null).
- `enable_ipv4` (Boolean) Whether IPv4 is enabled on the Docker network.
- `enable_ipv6` (Boolean) Whether IPv6 is enabled on the Docker network.
- `ingress` (Boolean) Whether the network is a Swarm ingress network used for the routing mesh.
- `internal` (Boolean) Whether the network is restricted to internal use only (no external connectivity).
- `ipam_config` (Block List) List of IPAM configuration blocks defining subnets, gateways, and IP ranges. (see [below for nested schema](#nestedblock--ipam_config))
- `ipam_driver` (String) IPAM driver used to allocate IP addresses for the Docker network.
- `ipam_options` (Map of String) Driver-specific options passed to the IPAM driver.
- `labels` (Map of String) Key/value labels attached to the Docker network.
- `options` (Map of String) Driver-specific options passed to the Docker network driver.
- `scope` (String) Scope of the Docker network (local, global, or swarm).
- `swarm_node_id` (String) Swarm node ID where the network operation is targeted, when applicable.

### Read-Only

- `id` (String) Identifier of the resource.
- `resource_control_id` (Number) ID of the Portainer resource control associated with this Docker network.

## Notes on Arguments and Attributes

- `driver`: Defaults to `bridge`.
- `scope`: Defaults to `local`.
- `internal`: Defaults to `false`.
- `attachable`: Whether containers can be attached manually (default: `false`)
- `ingress`: Defaults to `false`.
- `config_only`: Defaults to `false`.
- `enable_ipv4`: Defaults to `true`.
- `enable_ipv6`: Defaults to `false`.
- `ipam_driver`: Defaults to `default`.
- `ipam_config.subnet`: The subnet in CIDR format (e.g. `192.168.0.0/24`)
- `id`: ID of the created Docker network (as returned by Portainer)

## Import

Docker networks can be imported using a composite ID in the form `<endpoint_id>:<network_id>`, where `<endpoint_id>` is the numeric ID of the Portainer environment and `<network_id>` is the Docker network ID (a string hash, not a number):

```shell
terraform import portainer_docker_network.example 1:a1b2c3d4e5f6
```

### Import by identity

Terraform 1.12 and later can also import by resource identity: the environment ID as `endpoint_id` and the Docker network ID as `id` in an `import` block. The ID string above keeps working.

```hcl
import {
  to       = portainer_docker_network.example
  identity = {
    endpoint_id = 1
    id          = "a1b2c3d4e5f6"
  }
}
```

`terraform query` (Terraform 1.14+) with the [`portainer_docker_network` list resource](../list-resources/docker_network.md) finds the objects to import and can generate the `import` blocks (`terraform query -generate-config-out=generated.tf`). The identity is stored in the state from v3.1.0 on; state written by v3.0.0 gets it on the next refresh, without a plan change. OpenTofu supports neither resource identity nor list resources; it keeps importing by ID.
