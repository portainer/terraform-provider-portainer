# portainer_stack_migrate (Resource)

The `portainer_stack_migrate` resource triggers migration of a stack from one Portainer environment (endpoint) to another. It re-creates the stack in the target environment before removing the original.

> Note: This is an action resource. It performs the migration on `terraform apply` and does not track ongoing state. Each apply triggers a new migration.

> **See also:** the [`portainer_stack_migrate` action](../actions/stack_migrate.md) (Terraform >= 1.14) runs the same operation on demand or from a lifecycle `action_trigger`, without a resource in state.

## Example Usage

```hcl
resource "portainer_stack_migrate" "move" {
  stack_id           = 5
  target_endpoint_id = 2
}
```

### Migrate with rename

```hcl
resource "portainer_stack_migrate" "move_renamed" {
  stack_id           = 5
  target_endpoint_id = 2
  stack_name         = "my-stack-production"
}
```

### Migrate to a Swarm environment

```hcl
resource "portainer_stack_migrate" "move_swarm" {
  stack_id           = 5
  target_endpoint_id = 3
  swarm_id           = "jpofkc0i9uo9wtx1zesuk649w"
}
```

## Schema

### Required

- `stack_id` (Number) Stack identifier to migrate.
- `target_endpoint_id` (Number) Target environment (endpoint) identifier to migrate the stack to.

### Optional

- `endpoint_id` (Number) Optional source environment (endpoint) identifier. Required for stacks created before Portainer 1.18.0.
- `is_helm` (Boolean) Whether the stack is a Helm release on Kubernetes. Business Edition only. Only sent when set to true.
- `stack_name` (String) New name for the stack after migration. If not set, the original name is kept.
- `swarm_id` (String) Swarm cluster identifier (required when migrating to a Swarm environment).

### Read-Only

- `id` (String) Identifier of the resource.
