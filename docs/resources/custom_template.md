# portainer_custom_template (Resource)

The `portainer_custom_template` resource allows you to manage Portainer Custom Templates.
You can create templates using inline content (`file_content`), from a local file (`file_path`), or from a Git repository.

## Example Usage

### Create Custom Template using `file_content`
```hcl
resource "portainer_custom_template" "example_string" {
  title        = "nginx-string"
  description  = "Template from inline string"
  note         = "This is from string"
  platform     = 1
  type         = 2
  file_content = <<-EOT
    version: "3"
    services:
      web:
        image: nginx
  EOT
}
```

### Create Custom Template from local file
```hcl
resource "portainer_custom_template" "example_file" {
  title        = "nginx-file"
  description  = "Template from file"
  note         = "Note here"
  platform     = 1
  type         = 2
  file_path    = "./templates/nginx.yml"
}
```

### Create Custom Template from Git repository
```hcl
resource "portainer_custom_template" "example_git" {
  title                   = "nginx-git"
  description             = "From Git"
  note                    = "Git-based template"
  platform                = 1
  type                    = 2
  repository_url          = "https://github.com/example/repo"
  repository_username     = "gituser"
  repository_password     = "supersecret"
  repository_reference    = "refs/heads/main"
  compose_file_path       = "docker-compose.yml"
  tlsskip_verify          = false
}
```

## Lifecycle & Behavior
Custom templates are immutable in Portainer. To update, you must destroy and recreate them.
> Only one of `file_content`, `file_path`, or `repository_url` must be specified.
- To delete an custom template created via Terraform, simply run:
```hcl
terraform destroy
```

- To modify a group (e.g., make it dynamic), update the attributes and re-apply:
```hcl
terraform apply
```

## Schema

### Required

- `description` (String) Short description of the custom template displayed in the Portainer UI.
- `note` (String) Additional note or instructions associated with the custom template.
- `platform` (Number) Target platform for the template: 1 = Linux, 2 = Windows.
- `title` (String) Title of the Portainer custom template.
- `type` (Number) Template type: 1 = Swarm stack, 2 = Compose stack, 3 = Kubernetes manifest.

### Optional

- `compose_file_path` (String) Path within the Git repository to the Compose or manifest file (defaults to `docker-compose.yml`).
- `edge_settings` (Block List) Defaults of an Edge stack deployed from this template (only for `edge_template = true`). Business Edition only; Community Edition ignores it. Only sent when the block is set. (see [below for nested schema](#nestedblock--edge_settings))
- `edge_template` (Boolean) Whether this template is exposed as an Edge template.
- `file_content` (String) Inline template body (Compose YAML, Kubernetes manifest, or Swarm stack file). Mutually exclusive with `file_path` and the repository fields.
- `file_path` (String) Path on the local filesystem to a file containing the template body. Mutually exclusive with `file_content` and the repository fields.
- `is_compose_format` (Boolean) Whether the Kubernetes manifest is provided in Compose format (only relevant for `type = 3`).
- `logo` (String) URL of the logo image displayed next to the template in the Portainer UI.
- `repository_authentication` (Boolean) Enable authentication for the Git repository (default: false).
- `repository_password` (String, Sensitive) Sensitive password or personal access token used to authenticate against the Git repository. Stored in state; use `repository_password_wo` to keep it out.
- `repository_password_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) Write-only Git password or personal access token (supports ephemeral values; never stored in Terraform state). Conflicts with `repository_password`. Requires Terraform 1.11 or later.
- `repository_password_wo_version` (Number) Version of `repository_password_wo`. Increment it to send a new value. Changing it forces resource recreation.
- `repository_reference` (String) Git reference (branch, tag, or commit) to check out (defaults to `refs/heads/main`).
- `repository_url` (String) URL of the Git repository hosting the template manifest.
- `repository_username` (String) Username used to authenticate against the Git repository.
- `source_id` (Number) ID of a Portainer Source (Git source) providing the repository URL and credentials. Portainer 2.43 and later. When set, `repository_url` and the repository credentials can be left out; `repository_reference` and `compose_file_path` still apply.
- `tlsskip_verify` (Boolean) Whether to skip TLS verification when cloning the Git repository.
- `variables` (List of Map of String) List of template variable definitions (name, label, description, defaultValue) used for parameterized templates.

## Notes on Arguments and Attributes

- `edge_template`: Defaults to `false`.
- `is_compose_format`: Defaults to `false`.
- `file_content`: Inline Compose content (exclusive with `file_path` and `repository_url`)
- `file_path`: Path to local Compose file (exclusive with `file_content` and `repository_url`)
- `tlsskip_verify`: Defaults to `false`.
- `repository_username`: Git username (required if `repository_authentication = true`)
- `repository_password`: Git password/token (required if `repository_authentication = true`)
- `repository_password_wo_version`: Forces recreation, like `repository_password`
- `edge_settings.per_device_configs_match_type`: Requires `per_device_configs_path`
- `edge_settings.per_device_configs_group_match_type`: Requires `per_device_configs_path`
- `edge_settings.stagger_config`: Staggered rollout, the same block as on [`portainer_edge_stack`](edge_stack.md#nestedblock--stagger_config)
- `id`: ID of the custom template in Portainer.

## Arguments by Deployment Method

### For `String-based` Template
Arguments: `file_content`.

### For `File-based` Template
Arguments: `file_path`.

### For `Repository-based` Template
Arguments: `repository_url`, `source_id`, `repository_reference`, `compose_file_path`, `tlsskip_verify`, `repository_authentication`, `repository_username`, `repository_password`, `repository_password_wo`, `repository_password_wo_version`.

### `edge_settings` Block

> **Business Edition only.** Community Edition ignores it. Only sent (on create and update) when the block is set; read back only while it is configured, with unset attributes left unset.

```hcl
resource "portainer_custom_template" "edge" {
  title         = "edge-web"
  description   = "Edge web stack"
  note          = "Edge template"
  platform      = 1
  type          = 2
  edge_template = true
  file_content  = file("docker-compose.yml")

  edge_settings {
    retry_deploy  = true
    retry_period  = 300
    relative_path = "/opt/edge"
    stagger_config {
      stagger_option  = "parallel"
      parallel_option = "fixed"
      device_number   = 5
    }
  }
}
```

## Import

Custom templates can be imported using their numeric ID:

```shell
terraform import portainer_custom_template.example 42
```

### Import by identity

Terraform 1.12 and later can also import by resource identity: the object's numeric ID as `id` in an `import` block. The ID string above keeps working.

```hcl
import {
  to       = portainer_custom_template.example
  identity = {
    id = "9"
  }
}
```

`terraform query` (Terraform 1.14+) with the [`portainer_custom_template` list resource](../list-resources/custom_template.md) finds the objects to import and can generate the `import` blocks (`terraform query -generate-config-out=generated.tf`). The identity is stored in the state from v3.1.0 on; state written by v3.0.0 gets it on the next refresh, without a plan change. OpenTofu supports neither resource identity nor list resources; it keeps importing by ID.
