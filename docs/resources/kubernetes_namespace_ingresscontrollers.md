# portainer_kubernetes_namespace_ingresscontrollers (Resource)

The `portainer_kubernetes_namespace_ingresscontrollers` resource allows you to manage (block/unblock) ingress controllers per namespace in a Kubernetes environment within Portainer.

## Example Usage
```hcl
resource "portainer_kubernetes_namespace_ingresscontrollers" "test" {
  environment_id = 1
  namespace      = "default"

  controllers {
    name         = "nginx"
    class_name   = "nginx"
    type         = "nginx"
    availability = true
    used         = true
    new          = false
  }
}
```

## Lifecycle & Behavior
- This resource updates ingress controller configurations via the Portainer API.
- You can enable, disable or modify ingress controllers declaratively via Terraform; changes apply in place.
- Per-namespace availability only takes effect when the environment has `ingress_availability_per_namespace` enabled (see `portainer_kubernetes_environment_config`); otherwise Portainer reports every controller as available.
- A controller blocked for the whole environment is not listed for the namespace and shows as drift.
- Portainer only takes `class_name` and `availability`; `name`, `type`, `used` and `new` are informational and a difference in them is not planned once the controller is in state. Every `class_name` must exist in the cluster, otherwise the apply fails.
- Destroying the resource makes the listed controllers available in the namespace again (Portainer's default).

## Schema

### Required

- `environment_id` (Number) Identifier of the Portainer Kubernetes environment hosting the namespace.
- `namespace` (String) Kubernetes namespace whose ingress controller allow-list is being configured.

### Optional

- `controllers` (Block List) List of ingress controllers allowed for the namespace. (see [below for nested schema](#nestedblock--controllers))

### Read-Only

- `id` (String) Identifier of the namespace, `<environment_id>:<namespace>`.

<a id="nestedblock--controllers"></a>
### Nested Schema for `controllers`

Required:

- `availability` (Boolean) Whether the ingress controller is exposed for selection in the Portainer UI.
- `class_name` (String) Kubernetes IngressClass name associated with the controller. Must exist in the cluster.
- `name` (String) Display name of the ingress controller. Informational: Portainer ignores it.
- `new` (Boolean) Whether Portainer treats the controller as newly registered. Informational: Portainer ignores it.
- `type` (String) Type of the ingress controller (for example `nginx`, `traefik`, `custom`). Informational: Portainer ignores it.
- `used` (Boolean) Whether the ingress controller is in use by workloads. Informational: Portainer ignores it.

## Import

Namespace ingress controller settings can be imported using `environment_id:namespace`:

```shell
terraform import portainer_kubernetes_namespace_ingresscontrollers.example 4:default
```
