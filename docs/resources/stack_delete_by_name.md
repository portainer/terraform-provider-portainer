# portainer_stack_delete_by_name (Resource)

The `portainer_stack_delete_by_name` resource removes Kubernetes stacks by name, which is the only way to clear a stack Terraform does not have an ID for — typically one deployed outside Portainer and only discovered by it.

This is an **action resource**: the work happens when it is created, and destroying it does nothing. It is not a way to manage a stack's lifecycle; use `portainer_stack` for stacks Terraform owns. Reach for this only to clean up something Terraform never created, usually before adopting a namespace.

> **See also:** the [`portainer_stack_delete_by_name` action](../actions/stack_delete_by_name.md) (Terraform >= 1.14) runs the same operation on demand or from a lifecycle `action_trigger`, without a resource in state.

## Example Usage

```hcl
resource "portainer_stack_delete_by_name" "legacy" {
  name        = "legacy-app"
  namespace   = "legacy-apps"
  endpoint_id = 4
  external    = true
}
```

## Schema

### Required

- `endpoint_id` (Number) Identifier of the environment the stack was deployed to.
- `name` (String) Name of the Kubernetes stack to remove. Every stack with this name in the target environment is removed.
- `namespace` (String) Kubernetes namespace the stack was deployed into. Portainer requires it, even though its API specification does not list it.

### Optional

- `external` (Boolean) Whether the stack was created outside Portainer. Set it to true to remove a stack Portainer only discovered, rather than one it deployed.

### Read-Only

- `id` (String) Identifier of the resource.

## Notes on Arguments and Attributes

- `id`: Synthetic identifier in the form `<endpoint_id>/<name>/deleted/<timestamp>`.

All arguments force a new resource.

## Attributes Reference

A stack that is already gone is treated as success — that is the state this resource asks for.
