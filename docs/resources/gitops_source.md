# portainer_gitops_source (Resource)

The `portainer_gitops_source` resource manages a Git source in Portainer's GitOps feature. A source is the repository Portainer polls; workflows then deploy artifacts from it.

## Example Usage

### Public repository

```hcl
resource "portainer_gitops_source" "infra" {
  url      = "https://github.com/acme/infra.git"
  name     = "infra"
  interval = "5m"
  public   = true
}
```

### Private repository with access control

```hcl
resource "portainer_gitops_source" "apps" {
  url      = "https://github.com/acme/apps.git"
  name     = "apps"
  interval = "10m"

  username = "ci-bot"
  password = var.git_token

  public        = false
  user_accesses = [portainer_user.deployer.id]
  team_accesses = [portainer_team.platform.id]
}
```

Validate the credentials before creating the source with the `portainer_gitops_source_connection` data source.

## Schema

### Required

- `url` (String) URL of the Git repository the source syncs from. Portainer stores it normalized (without a trailing `/` or `.git`); such differences are not shown as changes.

### Optional

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `administrators_only` (Boolean) Whether the source is restricted to administrators. Only honoured at creation time; Portainer's update API does not carry this field.
- `interval` (String) Polling interval for the repository as a Go duration string (for example `5m`). Leave unset to keep Portainer's default.
- `name` (String) Name of the GitOps source as displayed in Portainer. Portainer derives one from the repository URL when this is not set.
- `password` (String, Sensitive) Password or personal access token paired with `username`. Portainer never returns it, so it is kept from configuration and cannot detect drift. Use `password_wo` to keep it out of state.
- `password_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) Write-only password or personal access token paired with `username` (supports ephemeral values; never stored in Terraform state). Conflicts with `password`. Requires Terraform 1.11 or later.
- `password_wo_version` (Number) Version of `password_wo`. Increment it to send a new value.
- `public` (Boolean) Whether every user can use this source. Changing it is applied through the source's access-control endpoint.
- `team_accesses` (List of Number) IDs of teams granted access to the source. Applied through the source's access-control endpoint.
- `tls_skip_verify` (Boolean) Whether to skip TLS certificate verification when contacting the Git repository.
- `user_accesses` (List of Number) IDs of users granted access to the source. Applied through the source's access-control endpoint.
- `username` (String) Username used to authenticate against the Git repository. Leave unset for a public repository.

### Read-Only

- `id` (String) Identifier of the resource.
- `last_sync` (Number) Unix timestamp of the last successful synchronisation, zero when the source has never synced.
- `status` (String) Sync status of the source: `healthy`, `syncing`, `error`, `paused` or `unknown`.
- `status_error` (String) Error reported by the last synchronisation attempt, empty while the source is healthy.
- `type` (String) Source type reported by Portainer: `git`, `helm` or `oci`. This resource always creates a `git` source.

## Notes on Arguments and Attributes

- `administrators_only`: Only honoured at creation time — changing it replaces the resource.
- `id`: Identifier of the GitOps source.

Portainer splits an update across two endpoints: `url`, `name`, `interval`, `tls_skip_verify` and the credentials go to the source itself, while `public`, `user_accesses` and `team_accesses` go to its access-control endpoint. The provider calls each only when its own fields changed.

`password` is never returned by the API, so it cannot be checked for drift — a password changed in the Portainer UI stays invisible to Terraform until the value in the configuration changes.

## Import

GitOps sources can be imported using their numeric ID:

```shell
terraform import portainer_gitops_source.infra 12
```

`password` is not part of the imported state — set it in the configuration afterwards.

### Import by identity

Terraform 1.12 and later can also import by resource identity: the object's numeric ID as `id` in an `import` block. The ID string above keeps working.

```hcl
import {
  to       = portainer_gitops_source.example
  identity = {
    id = "12"
  }
}
```

`terraform query` (Terraform 1.14+) with the [`portainer_gitops_source` list resource](../list-resources/gitops_source.md) finds the objects to import and can generate the `import` blocks (`terraform query -generate-config-out=generated.tf`). The identity is stored in the state from v3.1.0 on; state written by v3.0.0 gets it on the next refresh, without a plan change. OpenTofu supports neither resource identity nor list resources; it keeps importing by ID.
