# portainer_registry_connection (Data Source)

The `portainer_registry_connection` data source asks Portainer to test whether it can reach and authenticate against a container registry, before a `portainer_registry` is created with the same credentials.

## Example Usage

```hcl
data "portainer_registry_connection" "harbor" {
  url           = "registry.example.com"
  type          = 3
  username      = "robot$ci"
  password      = var.registry_password
  tls           = true
  fail_on_error = true
}
```

## Schema

### Required

- `password` (String, Sensitive) Password or token paired with `username`.
- `type` (Number) Registry type: 1 = Quay, 2 = Azure, 3 = Custom, 4 = GitLab, 5 = ProGet, 6 = DockerHub, 7 = ECR, 8 = GitHub.
- `url` (String) URL of the registry to test, without a scheme for most types (for example `registry.example.com`).
- `username` (String) Username used for the test. Portainer requires credentials for every registry type, including public ones.

### Optional

- `fail_on_error` (Boolean) Whether an unreachable registry makes the data source itself fail. Defaults to false, which reports the outcome in `success` and `message`.
- `tls` (Boolean) Whether the registry is contacted over TLS.

### Read-Only

- `id` (String) Identifier of the test: registry-ping-<url>.
- `message` (String) Message returned by Portainer describing the outcome, carrying the reason on failure.
- `success` (Boolean) Whether Portainer could reach and authenticate against the registry.
