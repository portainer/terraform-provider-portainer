# portainer_alerting_rule_environments (Data Source)

> **Business Edition only.** This endpoint does not exist in Portainer CE.

Reports where an alert rule actually landed, broken down by endpoint group.

Attaching a rule to an endpoint group is not the same as the rule being evaluated there: an agent can be too old, or an environment the wrong type. This data source is what tells you whether the attachment did anything.

## Example Usage

```hcl
data "portainer_alerting_rule_environments" "cpu_saturation" {
  rule_id = portainer_alerting_rule_groups.cpu_saturation.rule_id
}

output "alert_rule_undelivered" {
  value = data.portainer_alerting_rule_environments.cpu_saturation.error
}
```

- `rule_id` (Number) Identifier of the alert rule to report on.

### Read-Only

- `active` (Number) Number of environments where the rule is being evaluated.
- `error` (Number) Number of environments where delivering the rule failed. A non-zero value is the one worth alerting on.
- `excluded` (Number) Number of environments deliberately left out of the rule.
- `groups` (List of Object) Delivery status broken down by endpoint group. (see [below for nested schema](#nestedatt--groups))
- `id` (String) Identifier of the data source.
- `not_supported` (Number) Number of environments that cannot run the rule, typically an agent too old or an environment of the wrong type.
- `pending` (Number) Number of environments where the rule has not been delivered yet.
- `total` (Number) Number of environments the rule reaches, across every status below.
