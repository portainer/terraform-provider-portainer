# portainer_kubernetes_events (Data Source)

Reads Kubernetes events, cluster-wide or for one namespace. Events are usually what explains a workload that will not start.

## Example Usage

```hcl
data "portainer_kubernetes_events" "prod" {
  environment_id = 1
  namespace      = "prod"
}

output "problems" {
  value = [
    for e in data.portainer_kubernetes_events.prod.events : "${e.kind}/${e.name}: ${e.reason} - ${e.message}"
    if e.type == "Warning"
  ]
}
```

## Schema

### Required

- `environment_id` (Number) Environment (endpoint) identifier of the Kubernetes environment to query.

### Optional

- `namespace` (String) Namespace to read events from. Leave unset to read events across every namespace the API token can access.
- `resource_id` (String) Only return events for the object with this UID. Cluster-wide queries only.

### Read-Only

- `events` (List of Object) Events matching the query, as Kubernetes reports them. Events are short-lived — Kubernetes discards them after about an hour by default. (see [below for nested schema](#nestedatt--events))
- `id` (String) Identifier of the resource.
- `warning_count` (Number) Number of returned events of type `Warning`, which is what usually explains a workload that will not start.
