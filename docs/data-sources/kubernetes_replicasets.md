# portainer_kubernetes_replicasets (Data Source)

The `portainer_kubernetes_replicasets` data source lists Kubernetes replica sets in a namespace. Its main use is discovering the rollout history of a deployment: each replica set carries the revision it represents, which is exactly what `portainer_kubernetes_deployment_rollback` takes as its target.

Requires Portainer **2.45.0** or newer.

## Example Usage

```hcl
data "portainer_kubernetes_replicasets" "web" {
  environment_id = 1
  namespace      = "default"
  deployment     = "web"
}

output "web_revisions" {
  value = {
    for rs in data.portainer_kubernetes_replicasets.web.replicasets : rs.name => rs.revision
  }
}
```

## Schema

### Required

- `environment_id` (Number) Environment (endpoint) identifier of the Kubernetes environment to query.
- `namespace` (String) Namespace whose replica sets are listed.

### Optional

- `deployment` (String) Only return replica sets owned by this deployment. Combined with `revision` on each result, this is how a rollback target is discovered.
- `field_selector` (String) Kubernetes field selector used to filter the replica sets (for example `metadata.name=web-1234`).
- `label_selector` (String) Kubernetes label selector used to filter the replica sets (for example `app=nginx`).

### Read-Only

- `id` (String) Identifier of the resource.
- `replicasets` (List of Object) Replica sets matching the query, in the order returned by the Kubernetes API. (see [below for nested schema](#nestedatt--replicasets))
