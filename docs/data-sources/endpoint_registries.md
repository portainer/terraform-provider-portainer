# portainer_endpoint_registries (Data Source)

Lists the registries a given environment can pull from, and optionally the Docker Hub pull rate limit that applies to it.

## Example Usage

```hcl
data "portainer_endpoint_registries" "prod" {
  environment_id        = 1
  dockerhub_registry_id = 6
}

# Do not start a large rollout on the last few pulls of the window.
output "dockerhub_headroom" {
  value = "${data.portainer_endpoint_registries.prod.dockerhub_rate_remaining} of ${data.portainer_endpoint_registries.prod.dockerhub_rate_limit}"
}
```

## Schema

### Required

- `environment_id` (Number) Environment (endpoint) identifier whose accessible registries are listed.

### Optional

- `dockerhub_registry_id` (Number) Identifier of a Docker Hub registry whose pull rate limit should also be fetched. Leave unset to skip that lookup.
- `namespace` (String) Kubernetes namespace to scope the list to, for an environment where registry access is granted per namespace.

### Read-Only

- `dockerhub_rate_limit` (Number) Docker Hub pull rate limit for the registry named by `dockerhub_registry_id`, zero when that argument is unset.
- `dockerhub_rate_remaining` (Number) Pulls still available within the current window. Watch this before a large rollout that pulls from Docker Hub.
- `id` (String) Identifier of the data source.
- `registries` (List of Object) Registries this environment can pull from. (see [below for nested schema](#nestedatt--registries))

## Attributes Reference

**Credentials are deliberately not exposed.** Portainer's API returns the full registry object, including its password and any access token; this data source maps neither, because copying registry credentials into every state file that reads it would be a liability and nothing in Terraform needs them.
