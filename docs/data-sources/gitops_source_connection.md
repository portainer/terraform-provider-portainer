# portainer_gitops_source_connection (Data Source)

The `portainer_gitops_source_connection` data source asks Portainer to test whether it can reach and authenticate against a Git repository. It works both for a repository that is not stored yet — to validate credentials before creating a `portainer_gitops_source` — and for an existing source.

## Example Usage

### Validate credentials before creating a source

```hcl
data "portainer_gitops_source_connection" "check" {
  url             = "https://github.com/acme/infra.git"
  username        = "ci-bot"
  password        = var.git_token
  fail_on_error   = true
}

resource "portainer_gitops_source" "infra" {
  depends_on = [data.portainer_gitops_source_connection.check]

  url      = "https://github.com/acme/infra.git"
  username = "ci-bot"
  password = var.git_token
}
```

### Re-test a stored source

```hcl
data "portainer_gitops_source_connection" "infra" {
  source_id = portainer_gitops_source.infra.id
}

output "infra_reachable" {
  value = data.portainer_gitops_source_connection.infra.success
}
```

## Schema

### Optional

- `fail_on_error` (Boolean) Whether a failing connection makes the data source itself fail. Defaults to false, which reports the outcome in `success` and `error`.
- `password` (String, Sensitive) Password or personal access token paired with `username`.
- `source_id` (Number) Identifier of a stored GitOps source to test. Mutually exclusive with `url`; exactly one of the two is required.
- `tls_skip_verify` (Boolean) Whether to skip TLS certificate verification during the test.
- `url` (String) Repository URL to test without storing a source, for validating credentials before creating one. Mutually exclusive with `source_id`.
- `username` (String) Username used for the test. Leave unset for an anonymous repository.

### Read-Only

- `error` (String) Reason the connection failed, empty on success.
- `id` (String) Identifier of the data source.
- `success` (Boolean) Whether Portainer could reach and authenticate against the repository.
