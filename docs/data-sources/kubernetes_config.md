# portainer_kubernetes_config (Data Source)

Generates a kubeconfig for the Kubernetes environments the calling user can reach, the same file Portainer's UI offers for download.

## Example Usage

```hcl
data "portainer_kubernetes_config" "prod" {
  environment_ids = [1, 2]
}

resource "local_sensitive_file" "kubeconfig" {
  filename = "${path.module}/kubeconfig.yaml"
  content  = data.portainer_kubernetes_config.prod.kubeconfig
}
```

## Schema

### Optional

- `environment_ids` (List of Number) Environments to include in the generated kubeconfig. Leave unset to include every Kubernetes environment the API token can reach.
- `exclude_environment_ids` (List of Number) Environments to leave out of the generated kubeconfig.

### Read-Only

- `id` (String) Identifier of the resource.
- `kubeconfig` (String, Sensitive) The generated kubeconfig, as YAML. It carries a bearer token for the calling user, so it is a credential in its own right and is stored in state as a sensitive value.

## Attributes Reference

**The kubeconfig carries a bearer token for the calling user**, so it is a credential in its own right. It is marked sensitive, but it still lands in Terraform state — treat that state accordingly, and prefer a short `kubeconfig_expiry` in Portainer's settings.

See also: the [`portainer_kubernetes_config` ephemeral resource](../ephemeral-resources/kubernetes_config.md) keeps the secret out of the plan and the state (Terraform >= 1.10, OpenTofu >= 1.11).
