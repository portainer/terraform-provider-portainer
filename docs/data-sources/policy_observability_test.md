# portainer_policy_observability_test (Data Source)

> **Business Edition only.** This endpoint does not exist in Portainer CE.

Checks whether Portainer can reach a OneUptime instance with the given details, before a policy is pointed at it.

## Example Usage

```hcl
data "portainer_policy_observability_test" "oneuptime" {
  one_uptime_url = "https://oneuptime.example.com"
  api_key        = var.oneuptime_api_key
  project_id     = var.oneuptime_project
}
```

## Schema

### Required

- `one_uptime_url` (String) URL of the OneUptime instance to test against.

### Optional

- `api_key` (String, Sensitive) OneUptime API key to authenticate with.
- `auto_provision_ingestion_key` (Boolean) Whether the test should provision an ingestion key as part of the check.
- `auto_rotate_key` (Boolean) Whether the test should rotate the key as part of the check.
- `fail_on_error` (Boolean) Whether a failed connection fails the plan. Defaults to `true`, which is the point of a pre-flight check; set it to `false` to branch on `success` instead.
- `policy_id` (Number) Existing policy to test the connection for, when there is one.
- `project_id` (String) OneUptime project the policy would report into.
- `tls_skip_verify` (Boolean) Whether to skip verification of the OneUptime server's TLS certificate.

### Read-Only

- `id` (String) Identifier of the data source.
- `message` (String) What Portainer reported about the attempt.
- `success` (Boolean) Whether Portainer could reach OneUptime with these details.

## Attributes Reference

The credentials are omitted from the request when unset, so a blank key is never sent and rejected for the wrong reason.

`fail_on_error` defaults to `true`, which is the point of a pre-flight check. Set it to `false` to read `success` and `message` and branch on them instead.
