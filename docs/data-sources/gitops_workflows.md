# portainer_gitops_workflows (Data Source)

The `portainer_gitops_workflows` data source lists Portainer's GitOps workflows with optional filtering and paging, together with the status summary.

A workflow has three phases — source, artifact and target — each with its own status. The `healthy` attribute is true only when all three report `healthy`, which is what Portainer's UI shows as a green workflow.

## Example Usage

```hcl
data "portainer_gitops_workflows" "all" {
  platform     = "kubernetes"
  endpoint_ids = [3, 4]
}

output "failing_workflows" {
  value = [
    for w in data.portainer_gitops_workflows.all.workflows :
    "${w.name}: source=${w.source_status} artifact=${w.artifact_status} target=${w.target_status}"
    if !w.healthy
  ]
}
```

## Schema

### Optional

- `endpoint_ids` (List of Number) Only return workflows deploying to these environment identifiers.
- `limit` (Number) Maximum number of results to return. Leave unset to let Portainer decide.
- `order` (String) Sort direction, `asc` or `desc`.
- `platform` (String) Only return workflows deploying to this platform.
- `search` (String) Free-text filter matched against the workflow name.
- `sort` (String) Field to sort the results by, as accepted by the Portainer API (for example `name`).
- `start` (Number) Zero-based index of the first result to return, for paging through a large list.
- `status` (String) Only return workflows in this status. `drifted` requires Portainer Business Edition 3.0 or later.
- `type` (String) Only return workflows with at least one artifact of this type. `gitopsDeployment`, an artifact on the `reconcile` engine, requires Portainer Business Edition 3.0 or later.

## Notes on Arguments and Attributes

- `type`: Only return workflows with an artifact of this type: `stack`, `edgeStack` or, on Portainer BE 3.0 or later, `gitopsDeployment` (the `reconcile` engine).
- `platform`: Only return workflows for this platform: `dockerStandalone`, `dockerSwarm`, `kubernetes`.
- `summary`: Exactly one element with the counts `healthy`, `syncing`, `error`, `paused`, `unknown` and `drifted` (always 0 before Portainer BE 3.0).

## Attributes Reference

The summary comes from its own Portainer endpoint and is not filtered by the arguments above.
