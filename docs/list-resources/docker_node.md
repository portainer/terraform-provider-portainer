# portainer_docker_node (List Resource)

The `portainer_docker_node` list resource lists the nodes of the Docker Swarm of a Portainer environment for `terraform query`, so existing objects can be found and imported into the [`portainer_docker_node`](../resources/docker_node.md) resource. Each result carries the resource identity (`endpoint_id`, `node_id`) and, with `include_resource = true`, the full resource as an import would read it.

> **Requirements:** Terraform 1.14 or later (`terraform query`, `*.tfquery.hcl` files). Importing the results by identity needs Terraform 1.12 or later. OpenTofu does not support list resources.

## Example Usage

### List everything in one environment (`main.tfquery.hcl`)

```hcl
list "portainer_docker_node" "all" {
  provider = portainer

  config {
    endpoint_id = 1
  }
}
```

### Filter and include the full resource

```hcl
list "portainer_docker_node" "selected" {
  provider         = portainer
  include_resource = true

  config {
    endpoint_id = 1
    name        = "worker-1"
  }
}
```

```shell
terraform query
# Write resource and import blocks for every result:
terraform query -generate-config-out=generated.tf
```

## Arguments Reference

Arguments of the `config` block. `endpoint_id` is required (Docker objects belong to one environment); `name` narrows the list. The `list` block itself takes Terraform's `provider`, `include_resource` (default `false`) and `limit` (default `100`).

## Schema

### Required

- `endpoint_id` (Number) ID of the Portainer environment (endpoint, a Docker Swarm manager) whose nodes are listed.

### Optional

- `name` (String) Only list the node with exactly this hostname.

## Attributes Reference

Each result has the node hostname as its display name and the identity:

| Identity attribute | Description |
|--------------------|-------------|
| `endpoint_id` | Numeric ID of the Portainer environment (a Swarm manager). |
| `node_id` | Docker Swarm node ID (the resource's `id` is `<endpoint_id>:<node_id>`). |

With `include_resource = true` a result also holds every attribute of the [`portainer_docker_node`](../resources/docker_node.md) resource, read the way an import reads it.

Destroying a `portainer_docker_node` removes the node from the Swarm, so review generated configuration before applying it.
