# portainer_docker_config (List Resource)

The `portainer_docker_config` list resource lists the Docker Swarm configs of a Portainer environment for `terraform query`, so existing objects can be found and imported into the [`portainer_docker_config`](../resources/docker_config.md) resource. Each result carries the resource identity (`endpoint_id`, `id`) and, with `include_resource = true`, the full resource as an import would read it.

> **Requirements:** Terraform 1.14 or later (`terraform query`, `*.tfquery.hcl` files). Importing the results by identity needs Terraform 1.12 or later. OpenTofu does not support list resources.

## Example Usage

### List everything in one environment (`main.tfquery.hcl`)

```hcl
list "portainer_docker_config" "all" {
  provider = portainer

  config {
    endpoint_id = 1
  }
}
```

### Filter and include the full resource

```hcl
list "portainer_docker_config" "selected" {
  provider         = portainer
  include_resource = true

  config {
    endpoint_id = 1
    name        = "app-config"
  }
}
```

```shell
terraform query
# Write resource and import blocks for every result:
terraform query -generate-config-out=generated.tf
```

## Arguments Reference

Arguments of the `config` block. `endpoint_id` is required (Docker objects belong to one environment); `name` narrows the list. The `list` block itself takes Terraform's `provider`, `include_resource` (default `false`) and `limit` (default `100`).

## Schema

### Required

- `endpoint_id` (Number) ID of the Portainer environment (endpoint) whose configs are listed.

### Optional

- `name` (String) Only list the configs with exactly this name.

## Attributes Reference

Each result has the config name as its display name and the identity:

| Identity attribute | Description |
|--------------------|-------------|
| `endpoint_id` | Numeric ID of the Portainer environment. |
| `id` | Docker Swarm config ID, the resource's `id`. |

With `include_resource = true` a result also holds every attribute of the [`portainer_docker_config`](../resources/docker_config.md) resource, read the way an import reads it.

The config data is not read back: `data` is null in a result, and the plan after importing one shows it as a change.
