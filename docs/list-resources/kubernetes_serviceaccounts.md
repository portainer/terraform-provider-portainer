# portainer_kubernetes_serviceaccounts (List Resource)

The `portainer_kubernetes_serviceaccounts` list resource lists the Kubernetes ServiceAccounts of a Portainer environment for `terraform query`, through Portainer's Kubernetes API proxy, so existing objects can be found and imported into the [`portainer_kubernetes_serviceaccounts`](../resources/kubernetes_serviceaccounts.md) resource. Each result carries the resource identity (`endpoint_id`, `namespace`, `name`) and, with `include_resource = true`, the full resource.

> **Requirements:** Terraform 1.14 or later (`terraform query`, `*.tfquery.hcl` files). Importing the results by identity needs Terraform 1.12 or later. OpenTofu does not support list resources.

## Example Usage

### List everything in one environment (`main.tfquery.hcl`)

```hcl
list "portainer_kubernetes_serviceaccounts" "all" {
  provider = portainer

  config {
    endpoint_id = 1
  }
}
```

### Filter and include the full resource

```hcl
list "portainer_kubernetes_serviceaccounts" "selected" {
  provider         = portainer
  include_resource = true

  config {
    endpoint_id = 1
    namespace   = "default"
  }
}
```

```shell
terraform query
# Write resource and import blocks for every result:
terraform query -generate-config-out=generated.tf
```

## Arguments Reference

Arguments of the `config` block. `endpoint_id` is required (Kubernetes objects belong to one environment); `namespace` narrows the list to one namespace, every namespace is listed without it. The `list` block itself takes Terraform's `provider`, `include_resource` (default `false`) and `limit` (default `100`).

### Required

## Attributes Reference

Each result has `<namespace>/<name>` as its display name and the identity:

| Identity attribute | Description |
|--------------------|-------------|
| `endpoint_id` | Numeric ID of the Portainer Kubernetes environment. |
| `namespace` | Namespace of the object. |
| `name` | Name of the object (`metadata.name`). |

With `include_resource = true` a result also holds every attribute of the [`portainer_kubernetes_serviceaccounts`](../resources/kubernetes_serviceaccounts.md) resource. Unlike an import, which leaves `manifest` empty, a result's `manifest` is the live object as YAML without what the API server manages (`status`, `uid`, `resourceVersion`, `generation`, `creationTimestamp`, `managedFields` and the `kubectl.kubernetes.io/last-applied-configuration` annotation), so `terraform query -generate-config-out` writes a usable configuration. It still holds the defaults the API server filled in; trim them as needed.

Objects controlled by another object (an `ownerReferences` entry with `controller: true`, such as the Jobs of a CronJob) are left out: managing them would fight their owner.
