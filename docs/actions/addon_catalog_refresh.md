# portainer_addon_catalog_refresh (Action)

> **Requires Portainer Business Edition 2.45.2 or later.** On Community Edition or an older server the refresh fails with an error that says so.

The `portainer_addon_catalog_refresh` action drops Portainer's cached addon catalog, so the next read loads it from the configured catalog source.

> **Requirements:** Terraform >= 1.14 (actions). OpenTofu does not support actions; there, and with older Terraform, use the [`portainer_addon_catalog_refresh` resource](../resources/addon_catalog_refresh.md), which runs the same operation when it is created.

## Example Usage

### Run it from a lifecycle `action_trigger`

```hcl
action "portainer_addon_catalog_refresh" "now" {}

resource "portainer_settings" "this" {
  # ... (addon catalog URL)

  lifecycle {
    action_trigger {
      events  = [after_update]
      actions = [action.portainer_addon_catalog_refresh.now]
    }
  }
}
```

### Run it on demand

```shell
terraform apply -invoke action.portainer_addon_catalog_refresh.now
```

## Lifecycle & Behavior

- The action runs only when it is invoked: from an `action_trigger` on the events listed there, or with `terraform apply -invoke`. A plan lists the invocations it would run; nothing is stored in state, so there is nothing to destroy and no `triggers` argument is needed to run it again.
- It sends the same requests as the `portainer_addon_catalog_refresh` resource does when it is created, with the same defaults, and fails the apply with the same errors.

## Arguments Reference

The action takes no arguments: its `config` block can be left out.

## Attributes Reference

Actions have no attributes: nothing they return can be referenced elsewhere in the configuration.
