# portainer_container_exec (Action)

The `portainer_container_exec` action runs a command in a container (`mode = "standalone"`) or in the running task of a Swarm service (`mode = "swarm"`).

> **Requirements:** Terraform >= 1.14 (actions). OpenTofu does not support actions; there, and with older Terraform, use the [`portainer_container_exec` resource](../resources/container_exec.md), which runs the same operation when it is created.

## Example Usage

### Run it from a lifecycle `action_trigger`

```hcl
action "portainer_container_exec" "migrate" {
  config {
    endpoint_id  = 1
    service_name = "app"
    command      = "php artisan migrate --force"
  }
}

resource "portainer_stack" "app" {
  # ...

  lifecycle {
    action_trigger {
      events  = [after_create, after_update]
      actions = [action.portainer_container_exec.migrate]
    }
  }
}
```

### Run it on demand

```shell
terraform apply -invoke action.portainer_container_exec.migrate
```

## Lifecycle & Behavior

- The action runs only when it is invoked: from an `action_trigger` on the events listed there, or with `terraform apply -invoke`. A plan lists the invocations it would run; nothing is stored in state, so there is nothing to destroy and no `triggers` argument is needed to run it again.
- It sends the same requests as the `portainer_container_exec` resource does when it is created, with the same defaults, and fails the apply with the same errors.
- The command's output is shown as a progress message, since an action has no `output` attribute to read it from.
- The command runs within a 5 minute timeout, the resource's default.

## Schema

### Required

- `command` (String) Shell command to execute inside the target container.
- `endpoint_id` (Number) Identifier of the Portainer endpoint hosting the container or Swarm service.
- `service_name` (String) Name of the container (standalone) or Swarm service in which the command should be executed.

### Optional

- `mode` (String) Deployment mode: 'standalone' (default) or 'swarm'
- `user` (String) User and optional group used to run the command inside the container (defaults to `root:root`).
- `wait` (Number) Initial delay in seconds before executing the command. Defaults to `0`.

## Attributes Reference

Actions have no attributes: nothing they return can be referenced elsewhere in the configuration.
