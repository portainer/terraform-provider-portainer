# portainer_backup_azure_execute (Action)

> **Business Edition only.** This endpoint does not exist in Portainer CE.

The `portainer_backup_azure_execute` action runs an Azure Blob backup once, outside the schedule. It takes the same Azure settings as `portainer_backup_azure_settings` and does not change the stored schedule.

> **Requirements:** Terraform >= 1.14 (actions). OpenTofu does not support actions; there, and with older Terraform, use the [`portainer_backup_azure_execute` resource](../resources/backup_azure_execute.md), which runs the same operation when it is created.

## Example Usage

### Run it from a lifecycle `action_trigger`

```hcl
action "portainer_backup_azure_execute" "now" {
  config {
    auth_method          = "storageAccountKey"
    storage_account_name = "portainerbackups"
    container_name       = "backups"
    storage_account_key  = var.storage_account_key
    password             = var.backup_password
  }
}

resource "terraform_data" "release" {
  input = var.release

  lifecycle {
    action_trigger {
      events  = [before_update]
      actions = [action.portainer_backup_azure_execute.now]
    }
  }
}
```

### Run it on demand

```shell
terraform apply -invoke action.portainer_backup_azure_execute.now
```

## Lifecycle & Behavior

- The action runs only when it is invoked: from an `action_trigger` on the events listed there, or with `terraform apply -invoke`. A plan lists the invocations it would run; nothing is stored in state, so there is nothing to destroy and no `triggers` argument is needed to run it again.
- It sends the same requests as the `portainer_backup_azure_execute` resource does when it is created, with the same defaults, and fails the apply with the same errors.
- The secrets have no `*_wo` twins in the action. Set them from sensitive variables so Terraform redacts them in its output.

## Schema

### Required

- `auth_method` (String) How Portainer authenticates against Azure: `servicePrincipalSecret`, `servicePrincipalCertificate`, `managedIdentity` or `storageAccountKey`. The other fields required depend on which one is chosen.
- `container_name` (String) Blob container the backups are written to.
- `storage_account_name` (String) Name of the Azure storage account holding the container.

### Optional

- `client_certificate` (String) PEM-encoded client certificate of the service principal. Used with `auth_method = "servicePrincipalCertificate"`. Action attributes cannot be marked sensitive: set it from a sensitive variable so Terraform redacts it in its output.
- `client_certificate_password` (String) Password protecting `client_certificate`, when it is encrypted. Action attributes cannot be marked sensitive: set it from a sensitive variable so Terraform redacts it in its output.
- `client_id` (String) Application (client) ID of the service principal.
- `client_secret` (String) Client secret of the service principal. Used with `auth_method = "servicePrincipalSecret"`. Action attributes cannot be marked sensitive: set it from a sensitive variable so Terraform redacts it in its output.
- `managed_identity_client_id` (String) Client ID of the user-assigned managed identity. Used with `auth_method = "managedIdentity"`; leave unset for a system-assigned identity.
- `password` (String) Password the backup archive itself is encrypted with. Leave unset for an unencrypted archive. Action attributes cannot be marked sensitive: set it from a sensitive variable so Terraform redacts it in its output.
- `service_url` (String) Blob service endpoint, for a sovereign cloud or a storage emulator. Leave unset for the public Azure cloud.
- `storage_account_key` (String) Storage account access key. Used with `auth_method = "storageAccountKey"`. Action attributes cannot be marked sensitive: set it from a sensitive variable so Terraform redacts it in its output.
- `tenant_id` (String) Entra ID tenant of the service principal. Used with both `servicePrincipal*` methods.

## Attributes Reference

Actions have no attributes: nothing they return can be referenced elsewhere in the configuration.
