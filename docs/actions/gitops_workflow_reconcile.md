# portainer_gitops_workflow_reconcile (Action)

> **Requires Portainer Business Edition 3.0 or later.** It only applies to a workflow on the `reconcile` engine.

The `portainer_gitops_workflow_reconcile` action asks a GitOps workflow to read its sources again and every environment running it to reconcile now, instead of waiting for its `reconcile_interval`. Portainer does not wait for the environments: success means the request was accepted.

> **Requirements:** Terraform >= 1.14 (actions). OpenTofu does not support actions; there, and with older Terraform, use the [`portainer_gitops_workflow_reconcile` resource](../resources/gitops_workflow_reconcile.md), which runs the same operation when it is created.

## Example Usage

### Run it from a lifecycle `action_trigger`

```hcl
action "portainer_gitops_workflow_reconcile" "now" {
  config {
    workflow_id = portainer_gitops_workflow.apps.id
  }
}

resource "terraform_data" "release" {
  input = var.release

  lifecycle {
    action_trigger {
      events  = [after_update]
      actions = [action.portainer_gitops_workflow_reconcile.now]
    }
  }
}
```

### Run it on demand

```shell
terraform apply -invoke action.portainer_gitops_workflow_reconcile.now
```

## Lifecycle & Behavior

- The action runs only when it is invoked: from an `action_trigger` on the events listed there, or with `terraform apply -invoke`. A plan lists the invocations it would run; nothing is stored in state, so there is nothing to destroy and no `triggers` argument is needed to run it again.
- It sends the same requests as the `portainer_gitops_workflow_reconcile` resource does when it is created, with the same defaults, and fails the apply with the same errors.
