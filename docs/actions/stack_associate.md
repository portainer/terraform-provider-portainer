# portainer_stack_associate (Action)

The `portainer_stack_associate` action associates an orphaned stack with an environment (endpoint), so Portainer manages it again.

> **Requirements:** Terraform >= 1.14 (actions). OpenTofu does not support actions; there, and with older Terraform, use the [`portainer_stack_associate` resource](../resources/stack_associate.md), which runs the same operation when it is created.

## Example Usage

### Run it from a lifecycle `action_trigger`

```hcl
action "portainer_stack_associate" "adopt" {
  config {
    stack_id    = 7
    endpoint_id = 2
    swarm_id    = "jpofkc0i9uo9wtx1zesuk649w"
  }
}

resource "portainer_environment" "swarm" {
  # ...

  lifecycle {
    action_trigger {
      events  = [after_create]
      actions = [action.portainer_stack_associate.adopt]
    }
  }
}
```

### Run it on demand

```shell
terraform apply -invoke action.portainer_stack_associate.adopt
```

## Lifecycle & Behavior

- The action runs only when it is invoked: from an `action_trigger` on the events listed there, or with `terraform apply -invoke`. A plan lists the invocations it would run; nothing is stored in state, so there is nothing to destroy and no `triggers` argument is needed to run it again.
- It sends the same requests as the `portainer_stack_associate` resource does when it is created, with the same defaults, and fails the apply with the same errors.
- Unlike the resource, the action does not check afterwards that the association still holds.

## Schema

### Required

- `endpoint_id` (Number) Identifier of the Portainer endpoint that should adopt the orphaned stack.
- `stack_id` (Number) Identifier of the orphaned Portainer stack to associate with an endpoint.
- `swarm_id` (String) Swarm cluster identifier (`Cluster.ID`) of the target endpoint when associating a Swarm stack.

### Optional

- `orphaned_running` (Boolean) Whether the orphaned stack is already running on the endpoint; controls Portainer's adoption behaviour. Defaults to `false`.

## Attributes Reference

Actions have no attributes: nothing they return can be referenced elsewhere in the configuration.
