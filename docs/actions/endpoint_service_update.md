# portainer_endpoint_service_update (Action)

The `portainer_endpoint_service_update` action force-updates a Docker Swarm service, optionally pulling its image first.

> **Requirements:** Terraform >= 1.14 (actions). OpenTofu does not support actions; there, and with older Terraform, use the [`portainer_endpoint_service_update` resource](../resources/endpoint_service_update.md), which runs the same operation when it is created.

## Example Usage

### Run it from a lifecycle `action_trigger`

```hcl
action "portainer_endpoint_service_update" "web" {
  config {
    endpoint_id  = 1
    service_name = "shop_web"
    pull_image   = true
  }
}

resource "terraform_data" "image" {
  input = var.image_tag

  lifecycle {
    action_trigger {
      events  = [after_update]
      actions = [action.portainer_endpoint_service_update.web]
    }
  }
}
```

### Run it on demand

```shell
terraform apply -invoke action.portainer_endpoint_service_update.web
```

## Lifecycle & Behavior

- The action runs only when it is invoked: from an `action_trigger` on the events listed there, or with `terraform apply -invoke`. A plan lists the invocations it would run; nothing is stored in state, so there is nothing to destroy and no `triggers` argument is needed to run it again.
- It sends the same requests as the `portainer_endpoint_service_update` resource does when it is created, with the same defaults, and fails the apply with the same errors.

## Schema

### Required

- `endpoint_id` (Number) Identifier of the Portainer endpoint hosting the Swarm service to force-update.
- `service_name` (String) Name of the Swarm service that should be force-updated.

### Optional

- `pull_image` (Boolean) Whether Portainer should pull the latest image when force-updating the service. Defaults to `false`.

## Attributes Reference

Actions have no attributes: nothing they return can be referenced elsewhere in the configuration.
