# portainer_kubernetes_deployment_scale (Action)

The `portainer_kubernetes_deployment_scale` action scales an existing Kubernetes deployment to a replica count through Portainer's scale API. Unlike the resource, it does not keep managing the replica count afterwards.

Requires Portainer **2.45.0** or newer.

> **Requirements:** Terraform >= 1.14 (actions). OpenTofu does not support actions; there, and with older Terraform, use the [`portainer_kubernetes_deployment_scale` resource](../resources/kubernetes_deployment_scale.md), which runs the same operation when it is created.

## Example Usage

### Run it from a lifecycle `action_trigger`

```hcl
action "portainer_kubernetes_deployment_scale" "down" {
  config {
    environment_id  = 1
    namespace       = "shop"
    deployment_name = "web"
    replicas        = 0
  }
}

resource "terraform_data" "maintenance" {
  input = var.maintenance

  lifecycle {
    action_trigger {
      events  = [after_update]
      actions = [action.portainer_kubernetes_deployment_scale.down]
    }
  }
}
```

### Run it on demand

```shell
terraform apply -invoke action.portainer_kubernetes_deployment_scale.down
```

## Lifecycle & Behavior

- The action runs only when it is invoked: from an `action_trigger` on the events listed there, or with `terraform apply -invoke`. A plan lists the invocations it would run; nothing is stored in state, so there is nothing to destroy and no `triggers` argument is needed to run it again.
- It sends the same requests as the `portainer_kubernetes_deployment_scale` resource does when it is created, with the same defaults, and fails the apply with the same errors.
