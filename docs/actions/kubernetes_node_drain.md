# portainer_kubernetes_node_drain (Action)

The `portainer_kubernetes_node_drain` action drains a Kubernetes node through Portainer, evicting its pods, like `kubectl drain`. The node stays cordoned afterwards.

Requires Portainer **2.45.0** or newer for the drain options.

> **Requirements:** Terraform >= 1.14 (actions). OpenTofu does not support actions; there, and with older Terraform, use the [`portainer_kubernetes_node_drain` resource](../resources/kubernetes_node_drain.md), which runs the same operation when it is created.

## Example Usage

### Run it from a lifecycle `action_trigger`

```hcl
action "portainer_kubernetes_node_drain" "worker1" {
  config {
    environment_id  = 1
    node_name       = "worker-1"
    timeout_seconds = 300
  }
}

resource "terraform_data" "maintenance" {
  input = var.maintenance_window

  lifecycle {
    action_trigger {
      events  = [after_update]
      actions = [action.portainer_kubernetes_node_drain.worker1]
    }
  }
}
```

### Run it on demand

```shell
terraform apply -invoke action.portainer_kubernetes_node_drain.worker1
```

## Lifecycle & Behavior

- The action runs only when it is invoked: from an `action_trigger` on the events listed there, or with `terraform apply -invoke`. A plan lists the invocations it would run; nothing is stored in state, so there is nothing to destroy and no `triggers` argument is needed to run it again.
- It sends the same requests as the `portainer_kubernetes_node_drain` resource does when it is created, with the same defaults, and fails the apply with the same errors.
- The defaults of the options are the resource's (and Portainer's own drain defaults).
- A progress message says which node is being drained and for how long the drain may take.

## Schema

### Required

- `environment_id` (Number) Identifier of the Portainer Kubernetes environment the node belongs to.
- `node_name` (String) Name of the Kubernetes node to drain.

### Optional

- `delete_empty_dir_data` (Boolean) Whether to evict pods that use an emptyDir volume, whose data is lost once the pod is deleted. Mirrors `kubectl drain --delete-emptydir-data`. Defaults to `true`.
- `disable_eviction` (Boolean) Whether to delete pods directly instead of going through the eviction API, which ignores any configured PodDisruptionBudget. Mirrors `kubectl drain --disable-eviction`. Defaults to `false`.
- `force` (Boolean) Whether to allow deletion of standalone pods that are not managed by a controller. Such pods are lost for good, so the drain refuses them unless this is enabled. Mirrors `kubectl drain --force`. Defaults to `false`.
- `grace_period_seconds` (Number) Termination grace period in seconds to apply to every evicted pod. `-1` keeps each pod's own grace period. Mirrors `kubectl drain --grace-period`. Defaults to `-1`.
- `ignore_daemon_sets` (Boolean) Whether to skip DaemonSet-managed pods, which would otherwise block the drain because their controller recreates them immediately. Mirrors `kubectl drain --ignore-daemonsets`. Defaults to `true`.
- `timeout_seconds` (Number) Overall time in seconds to wait for the drain to complete. Mirrors `kubectl drain --timeout`. Defaults to `60`.

## Attributes Reference
