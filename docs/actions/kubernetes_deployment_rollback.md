# portainer_kubernetes_deployment_rollback (Action)

The `portainer_kubernetes_deployment_rollback` action rolls a Kubernetes deployment back to an earlier rollout revision, the equivalent of `kubectl rollout undo`.

Requires Portainer **2.45.0** or newer.

> **Requirements:** Terraform >= 1.14 (actions). OpenTofu does not support actions; there, and with older Terraform, use the [`portainer_kubernetes_deployment_rollback` resource](../resources/kubernetes_deployment_rollback.md), which runs the same operation when it is created.

## Example Usage

### Run it from a lifecycle `action_trigger`

```hcl
action "portainer_kubernetes_deployment_rollback" "web" {
  config {
    environment_id  = 1
    namespace       = "shop"
    deployment_name = "web"
  }
}

resource "terraform_data" "rollback" {
  input = var.rollback_requested

  lifecycle {
    action_trigger {
      events    = [after_update]
      condition = var.rollback_requested
      actions   = [action.portainer_kubernetes_deployment_rollback.web]
    }
  }
}
```

### Run it on demand

```shell
terraform apply -invoke action.portainer_kubernetes_deployment_rollback.web
```

## Lifecycle & Behavior

- The action runs only when it is invoked: from an `action_trigger` on the events listed there, or with `terraform apply -invoke`. A plan lists the invocations it would run; nothing is stored in state, so there is nothing to destroy and no `triggers` argument is needed to run it again.
- It sends the same requests as the `portainer_kubernetes_deployment_rollback` resource does when it is created, with the same defaults, and fails the apply with the same errors.

## Schema

### Required

- `deployment_name` (String) Name of the deployment to roll back.
- `environment_id` (Number) Identifier of the Portainer Kubernetes environment the deployment belongs to.
- `namespace` (String) Namespace the deployment lives in.

### Optional

- `revision` (Number) Rollout revision to roll back to. `0` (the default) rolls back to the previous revision, matching `kubectl rollout undo`. Use the `portainer_kubernetes_replicasets` data source to discover the available revisions.

## Attributes Reference

Actions have no attributes: nothing they return can be referenced elsewhere in the configuration.
