# Portainer Terraform Provider

## Project Overview
Terraform provider for managing Portainer resources. Written in Go on terraform-plugin-framework, served over
protocol 5 (`internal/server.go`). Up to v3.0.0 it used Plugin SDK v2; the move kept every schema, state and
import ID (`internal/schema_compat_test.go` compares the schema with `internal/testdata/schema_v3.0.0.json`).

## Build & Test

```bash
make build              # Compile the provider binary
make install-plugin     # Install to local Terraform plugin directory
make fmt-check          # Check Terraform formatting
make fmt                # Format Terraform files
make go-fmt-check       # Check Go formatting
make go-fmt             # Format Go files
make validate           # Validate all Terraform configs
make docs-generate      # Regenerate docs/ from templates/ (tfplugindocs)
```

## Project Structure

- `internal/` - All provider Go source code
  - `fw_provider.go` - Provider schema, Configure and the type registries
  - `fw_register_*.go` - `init()` functions adding types to the registries
  - `fw_resource_*.go`, `fw_data_source_*.go` - Resources and data sources
  - `fw_ephemeral_*.go`, `fw_actions*.go`, `fw_list_*.go` - Ephemeral resources, actions, list resources
  - `fw_helpers.go` - Shared framework helpers; `helpers.go` - shared API helpers (`doJSON`, `isAPINotFound`, ...)
  - `provider.go` - `APIClient` and `newAPIClient`
  - `tools/` - Lint tools run in CI (schemalint, sensitivelint, docsdriftlint, importdoclint, apicoveragelint)
- `templates/` - Documentation templates (edit these); `docs/` is GENERATED by `make docs-generate`
- `examples/` - Example Terraform configurations per resource
- `e2e-tests/` - End-to-end test Terraform configs (run in CI)
- `.github/workflows/` - CI/CD (PR e2e tests, daily e2e tests, release, linting)

## Key Conventions

### Resource Implementation Pattern
See `internal/fw_resource_tag.go` for the smallest complete example:
1. A `resource.Resource` with `Metadata`, `Schema`, `Configure` (`configuredClient`), CRUD and usually `ImportState`.
2. Every attribute has a Description (schemalint) and secrets are Sensitive or write-only (sensitivelint).
3. Optional attributes the configuration leaves out stay null in state (never "" / 0 / false).
4. Read calls `resp.State.RemoveResource` when the object is gone (404).
5. API calls use the helpers in `helpers.go` (`doJSON`, `doJSONWithHeaders`, `doMultipart`), with `X-API-Key` or
   `Authorization: Bearer` JWT authentication.
6. Business Edition / version-gated APIs use `explainUnsupported` with the `requiresBE*` requirements.

### Testing
- Unit tests run real Terraform against `MockServer` (testhelpers_test.go) with `resource.UnitTest` /
  `resource.Test{IsUnitTest: true}`, `testProtoV5Factories` and `mockProviderConfig(mock)`. Never use
  `resource.ParallelTest` without `IsUnitTest: true`: it is skipped unless TF_ACC is set.
- Every resource has a `Test<Type>_UpgradeFromV300` test: state written by provider v3.0.0 must plan no change.
  It downloads v3.0.0; set `TF_CLI_CONFIG_FILE` to a CLI config with a filesystem mirror to avoid that.
- Acceptance tests (`TestAcc*`) need TF_ACC=1 and a live Portainer (`accPreCheck`).

### Naming
- Terraform resource names: `portainer_<resource>` (snake_case)
- Go types: `<name>Resource` / `<name>DataSource`, constructors `new<Name>Resource`
- API JSON fields: camelCase (e.g., `edgeGroupIDs`, `stackName`)

### Environment Types
- 1 = Docker, 2 = Agent, 3 = Azure, 4 = Edge Agent, 5 = Kubernetes, 6 = Kubernetes via agent, 7 = Kubernetes Edge Agent
- Portainer converts Edge Agent type 4 to type 7 after agent connects (handled by a plan modifier)
- Edge Agent (type 4/7): Tags must be applied via Update after creation (not in Create form params)

## E2E/PR Tests

Tests are organized in `e2e-tests/<resource>/` directories. Each has `main.tf`, `variables.tf`, and a resource `.tf` file.

CI runs tests in phases:
1. Setup (Portainer, k3d, kubectl)
2. Environment creation
3. Full-cycle tests (apply + destroy)
4. Apply-only tests
5. Swarm-specific tests
6. Edge agent tests
7. SSL test
